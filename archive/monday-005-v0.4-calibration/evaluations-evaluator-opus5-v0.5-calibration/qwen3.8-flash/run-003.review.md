Current state at 14:20 UTC: INC-2026-1109-01 is open, mitigated, and in verification. Root cause is not established. The verification window opened at 13:00 and closes at 14:30. What happened:
- 11:31: Release `batch-api@2026.11.09-r3` finished rolling out to both worker fleets. The changeset included three dependency bumps and a database connection-pool change lowering max pool size from 80 to 24 per worker.
- 11:38: Batch submission volume on fleet-a began climbing, reaching about three times the morning average, driven mainly by wonka-industries starting a large scheduled job.
- 11:42: First alert and incident start. `batch_api_5xx_rate` crossed its page threshold on fleet-a. Errors were `502` responses on `POST /v1/batch/jobs`. Priya acknowledged the page.
- 11:44: Confirmed errors were confined to fleet-a. fleet-b was serving normally with no elevated error rate.
- 11:47: Upstream object-storage provider was ruled out. Its status page showed no incident, and the Files API, which uses the same provider, stayed healthy.
- 12:31: Decision not to roll back `r3` yet. Rolling back would remove evidence needed to test whether the pool change is responsible, and the same release was running on fleet-b without harm. Mitigation chosen was to move traffic.
- 12:58: Mitigation applied. All Batch API traffic was cut over to fleet-b. fleet-a was drained and held out of rotation. Error rate on `POST /v1/batch/jobs` fell to 0.4% within two minutes. Baseline for the endpoint is 0.2%. At 14:12 the error rate was 0.3%.
- 13:00: Verification window opened. Northstar incident policy requires 90 minutes of continuous normal error rate on the affected endpoint before the incident may be declared resolved.
- 13:20: Error rate holding at 0.3–0.4%. Queue depth on fleet-b normal. No customer reports of new failures since the cutover.
- 13:52: Re-drive of jobs that failed during the window was in progress, roughly 60% complete, with no failures on re-drive.

Impact:
- 9 Batch API accounts made requests during the incident window.
- 7 accounts took failures, all on fleet-a: stark-industries, contoso, wayne-enterprises, globex, wonka-industries, umbrella-health, and initech.
- 2 accounts on fleet-b made Batch API requests during the window and had no failures: acme-corp and aperture-labs.
- Total Batch API requests in the 11:42–12:58 window: 58,900.
- Total failed Batch API requests in that window: 17,602.

- Fleet-a had 48,900 Batch API requests and 17,602 failures, about a 36.0% failure rate.
- Fleet-b had 10,000 Batch API requests and 0 failures.
